# Task API

A Go REST API for user-owned tasks. It uses PostgreSQL for persistence,
bcrypt for password hashing, and signed JWTs for authentication.

## Technology stack

- Go 1.27+
- `net/http`, `encoding/json`, and `net/http/httptest`
- PostgreSQL with `github.com/jackc/pgx/v5`
- `github.com/golang-jwt/jwt/v5`
- `golang.org/x/crypto/bcrypt`

## Windows setup

Create or use the PostgreSQL database named `tasks`. In PowerShell, set both
required environment variables in the same terminal used to start the API.
Replace the password and secret locally; do not commit them:

```powershell
$env:DATABASE_URL = "postgres://postgres:<password>@localhost:5432/tasks?sslmode=disable"
$env:JWT_SECRET = "<random-secret-at-least-32-characters>"
$env:PORT = "8080"
```

If port 8080 is occupied:

```powershell
$env:PORT = "8081"
```

Start the API:

```powershell
go run .
```

The application refuses to start if `DATABASE_URL` is missing or if
`JWT_SECRET` is missing or shorter than 32 characters.

## Database initialization

At startup, the application safely runs `CREATE TABLE IF NOT EXISTS` for
`users` and `tasks`, adds `tasks.user_id` if it is missing, and adds the
ownership foreign key if it is missing. It never drops, truncates, or recreates
existing tables.

The users schema is:

```sql
CREATE TABLE IF NOT EXISTS users (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    email TEXT NOT NULL UNIQUE,
    password_hash BYTEA NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

The task table keeps existing rows. Existing tasks created before ownership was
introduced may have `user_id` set to `NULL`; they are preserved but are not
visible to authenticated users until assigned to an owner.

## API usage

All task routes require:

```text
Authorization: Bearer <JWT_TOKEN>
```

Errors use the shape `{"error":"message"}`.

### Health

`GET /health` is public:

```powershell
curl.exe -i http://localhost:8080/health
```

### Register

`POST /register` is public:

```powershell
curl.exe -i `
  -X POST `
  -H "Content-Type: application/json" `
  -d '{"email":"test@example.com","password":"password123"}' `
  http://localhost:8080/register
```

Response: `201 Created`

```json
{"id":1,"email":"test@example.com"}
```

Passwords are stored only as bcrypt hashes. Duplicate email addresses return
`409 Conflict`.

### Login

`POST /login` is public:

```powershell
$login = curl.exe `
  -sS `
  -X POST `
  -H "Content-Type: application/json" `
  -d '{"email":"test@example.com","password":"password123"}' `
  http://localhost:8080/login

$token = ($login | ConvertFrom-Json).token
```

The token is valid for 24 hours. Never log or commit it.

### List tasks

```powershell
curl.exe -i `
  -H "Authorization: Bearer $token" `
  http://localhost:8080/tasks
```

### Create a task

```powershell
curl.exe -i `
  -X POST `
  -H "Authorization: Bearer $token" `
  -H "Content-Type: application/json" `
  -d '{"title":"Learn Go","description":"Build a REST API"}' `
  http://localhost:8080/tasks
```

### Get, update, and delete a task

```powershell
curl.exe -i -H "Authorization: Bearer $token" http://localhost:8080/tasks/1

curl.exe -i `
  -X PUT `
  -H "Authorization: Bearer $token" `
  -H "Content-Type: application/json" `
  -d '{"title":"Learn Go deeply","description":"Test the API","completed":true}' `
  http://localhost:8080/tasks/1

curl.exe -i `
  -X DELETE `
  -H "Authorization: Bearer $token" `
  http://localhost:8080/tasks/1
```

Users can only list, read, update, and delete their own tasks. A task owned by
another user behaves as not found.

## Validation and status codes

- `400 Bad Request`: malformed JSON, unknown fields, blank titles, invalid IDs
- `401 Unauthorized`: missing, invalid, or expired JWT; wrong login password
- `404 Not Found`: nonexistent task or task owned by another user
- `409 Conflict`: duplicate registration email
- `201 Created`: successful registration or task creation
- `200 OK`: successful health, login, list, get, or update
- `204 No Content`: successful deletion

## Development commands

```powershell
gofmt -w main.go storage.go postgres.go auth.go main_test.go models\task.go models\user.go
go test ./...
go vet ./...
```

Tests use an isolated in-memory store and do not modify PostgreSQL data.

## Frontend browser access

The API allows browser requests from the local Vite development origin:

```text
http://localhost:5173
```

It allows the `Authorization` and `Content-Type` headers and handles browser
`OPTIONS` preflight requests. Other origins are not allowed by the development
CORS policy. The frontend should send the JWT as:

```text
Authorization: Bearer <token>
```

## Secrets and limitations

Do not commit `DATABASE_URL`, `JWT_SECRET`, passwords, tokens, or `.env` files.
The repository `.gitignore` excludes local environment files.

Current limitations include no refresh tokens, logout/token revocation,
password reset, rate limiting, pagination, graceful shutdown, or migration
tool. Startup schema creation is intentionally conservative for this beginner
project and can later be replaced by versioned migrations.
